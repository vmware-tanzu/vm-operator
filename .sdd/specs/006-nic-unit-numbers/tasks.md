## Phase 3 — Mutation Webhook

> **The mutation webhook assigns NIC unit numbers**, following the disk / CD-ROM / controller pattern — including its `IsObjectUpgraded` gate, which is what keeps the webhook from guessing slots ahead of the backfill. See `plan.md`, "Mutation webhook".

- [ ] T008 [vmop-4075] Add a first-usable-unit notion to `NextAvailableUnitNumber` in `pkg/util/vmopv1/hardware.go` (which today scans `0..MaxSlots()-1` skipping a single `ReservedUnitNumber()`) and add `NICBusSpec` implementing `ControllerSpec` for the single implicit PCI bus — `MaxCount` of 1, no reserved unit, first unit 7. **Do not fork a NIC-local copy of the helper** — one helper with one set of semantics is the point of following the pattern. Two constraints (I21):

  1. **Do not widen the `ControllerSpec` interface itself.** Its four implementations are shipped API types in a *different Go module* — `api/v1alpha6/virtualmachine_hardware_types.go:71,104,128,171` (IDE/NVME/SATA/SCSI) — so adding a method there means four no-op API changes and an `api/` module edit this feature otherwise does not need. Instead declare an optional interface in `pkg/util/vmopv1` (e.g. `type firstUnitNumberer interface{ FirstUnitNumber() int32 }`), type-assert it inside `NextAvailableUnitNumber`, and default to 0 when a controller does not implement it. Only `NICBusSpec` implements it.
  2. **Keep `MaxSlots()` meaning "count".** SCSI returns 64 for units 0–63; a `NICBusSpec` returning 17 for a ten-slot bus drifts from that. Scan `first .. first+MaxSlots()-1` and have `NICBusSpec.MaxSlots()` return 10 — existing controllers (first = 0) are bit-for-bit unchanged.

## Phase 6 — Reconcile Matching

**Design (see `plan.md`, "Design: `unitNumber` is a device identity, not a slot"): `unitNumber`, once set, is the exclusive identifier linking a spec interface to a VC device — not a slot label a device occupies and can be moved between.** There is therefore no "slot-move", no Edit that changes `UnitNumber`, and no swap-collision logic to implement. A numbered interface is matched *only* by an exact lookup against the current device slots; a miss is a plain "no current hardware for this interface," handled entirely by the existing Add path (T018) plus the existing unmatched-device Remove cleanup (`reconcile.go:76-83`, already implemented, no changes needed).
